# 実装仕様

要件は [requirements.md](requirements.md)、画面は [mock/](mock/README.md) を参照。

## 1. 技術構成

| 項目 | 採用 |
|---|---|
| ビルド | Vite + TypeScript |
| UI | Preact（軽量。React と同じ書き方） |
| 形態素解析 | kuromoji.js（辞書ファイルは静的ファイルとして配信） |
| 読み上げ | Web Speech API `speechSynthesis` |
| LLM | Groq（OpenAI 互換の Chat Completions API、ストリーミング） |
| 保存 | localStorage |
| テスト | Vitest（ロジック）。画面の確認は手動で Windows の Edge |
| 配信 | GitHub Pages（GitHub Actions でビルドして公開） |

サーバーは持たない。外部への通信は Groq の API と、自サイトの静的ファイルだけ。

## 2. 全体の流れ

```
原文 ──▶ Groq（ストリーミング）──▶ 1 文ずつ受信
                                    │
                                    ▼
                         ┌─ 読みの決定（§4）─┐
                         │ 辞書 > この文だけ > AI > 自動解析 │
                         └──────────┬─────────┘
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
          表示用トークン列                   音声用テキスト（§5）
       （ルビ・色・クリック）           直した語だけかな、他は漢字
                                                    │
                                                    ▼
                                   speechSynthesis（文ごとに 1 発話）
```

## 3. Groq とのやり取り

### 3.1 エンドポイント

- 翻訳：`POST https://api.groq.com/openai/v1/chat/completions`（`stream: true`）
- 接続テスト：`GET https://api.groq.com/openai/v1/models`
- ヘッダー：`Authorization: Bearer <key>`。ブラウザから直接呼ぶ

### 3.2 モデル

| 表示 | model | 備考 |
|---|---|---|
| 速さ重視（既定） | `llama-3.3-70b-versatile` | 推論をしないので最初の出力が速い |
| 精度重視 | `openai/gpt-oss-120b` | `reasoning_effort: "low"` を付けて待ち時間を抑える |

どちらも Groq で使えるかは実装時に `/models` で確かめる（§9）。

### 3.3 出力形式（1 行 1 文の JSON = NDJSON）

文ごとに処理を始めたいので、1 文を 1 行の JSON で返させる。行が改行で終わった時点でパースする。

```json
{"i":0,"ja":"中国の習近平国家主席は日本の首相と会談した。","readings":[{"w":"習近平","r":"しゅうきんぺい"}]}
{"i":1,"ja":"一方、政府の有識者会議は皇位継承をめぐる議論を再開した。","readings":[{"w":"皇位継承","r":"こういけいしょう"}]}
```

- `readings` は、音声合成が読み間違えそうな語（固有名詞・難読語・訓読みと音読みを取り違えやすい熟語）だけにする。全語を返させない（トークン節約のため）
- 読みはひらがな
- JSON モード（`response_format`）は、ストリーミングと併用できるか分からないので使わない。プロンプトで形式を指定し、パースできない行は捨てて、その文だけ再要求する

### 3.4 プロンプト（骨子）

```
あなたは翻訳者です。入力を自然な日本語に訳し、1 文ごとに次の JSON を 1 行で出力してください。
{"i": 文番号, "ja": 訳文, "readings": [{"w": 語, "r": ひらがなの読み}]}
readings には、音声合成が読み間違えそうな語（固有名詞、難読語、読みを取り違えやすい熟語）だけを入れてください。
JSON 以外の文字は出力しないでください。
次の語は必ずこの読みを使ってください: <辞書のうち原文の訳に出そうな語>（任意）
```

### 3.5 長文の扱い

1 分あたりのトークン上限（無料プランで 8K〜12K 程度）に当たらないよう、原文は段落ごとに分けて順番に送る。1 段落の応答を読み終える前に次の段落を送ってよい。

### 3.6 エラー

| 状況 | 表示 |
|---|---|
| 401 | 「key が使えません」→ 設定画面へのリンク |
| 429 | 「Groq の無料枠の上限に達しました。しばらく待ってから再実行してください」。`retry-after` があれば待ち時間を出す |
| 通信エラー | 「Groq に接続できません」と再試行ボタン |

## 4. 読みの決定

### 4.1 優先順位

1 つの語の読みは、上から順に最初に見つかったものを使う。

1. **辞書**（利用者が登録した語）
2. **この文だけ**（修正パネルで「この文だけ直す」を選んだ語）
3. **AI**（Groq の `readings`）
4. **自動解析**（kuromoji の読み。カタカナをひらがなにする）

### 4.2 トークン化の手順

1. 訳文に対して、辞書の語と AI の `readings` の語を最長一致で探し、その範囲を 1 トークンに固定する
2. 残りの部分を kuromoji でトークン化する
3. 漢字を含むトークンを「語」とし、クリックできるようにする。かなと記号だけのトークンはクリックできない

```ts
type Fix = 'none' | 'ai' | 'once' | 'dict';

interface Token {
  id: number;
  sentence: number;   // 文番号
  text: string;       // 表示する文字列
  reading: string | null; // ひらがな。漢字を含まない語は null
  fix: Fix;           // 'none' は自動解析の読み
  start: number;      // 訳文の中での開始位置（文字数）
}
```

### 4.3 表示

| fix | 色 | ルビ |
|---|---|---|
| `ai` | オレンジ `#B4410C` | 常に出す |
| `once` / `dict` | 青 `#2F4BD8` | 常に出す |
| `none` | 本文の色、点線の下線 | 「ふりがなをすべて表示」のときだけ |

## 5. 音声に渡すテキスト

- `fix` が `none` 以外の語だけ、`reading`（ひらがな）に置き換える。ほかは漢字のまま渡す
  - 例：`中国のしゅうきんぺい国家主席は日本の首相と会談した。`
- 自動解析（kuromoji）の読みは表示用で、音声には使わない。エンジンが漢字から付けるアクセントを活かすため
- 置き換えのたびに「音声テキストの位置 → トークン id」の対応表を作る。ハイライトに使う（§6）

## 6. 読み上げ

- 1 文につき 1 つの `SpeechSynthesisUtterance` を作り、届いた順に `speechSynthesis.speak()` で積む
- `voice`・`rate` は設定から。声の一覧は `speechSynthesis.getVoices()` のうち `lang` が `ja` で始まるもの。一覧は `voiceschanged` イベントの後に取り直す
- ハイライト：`boundary` イベントの `charIndex` を §5 の対応表でトークンに変換する
  - `boundary` が来ない声の場合は、文単位のハイライトに切り替える
- 試聴（修正パネル・辞書）：その語の読みだけを 1 発話で読む
- 読みを直したら、その文の発話を作り直す。読み上げ中なら、その文から読み直す

## 7. 保存（localStorage）

| キー | 内容 |
|---|---|
| `yomiage.groqKey` | Groq の API key（文字列） |
| `yomiage.settings` | `{ "model": string, "voiceURI": string, "rate": number, "showAllRuby": boolean }` |
| `yomiage.dict` | `{ "version": 1, "entries": [{ "word": string, "reading": string, "source": "manual" \| "translation", "createdAt": string }] }` |

- 辞書の書き出しは `yomiage.dict` の値をそのまま JSON ファイルにする。読み込みは `version` を確かめ、同じ `word` があれば読み込んだ方で上書きする
- 「この文だけ」の修正は保存しない（画面を閉じたら消える）
- localStorage が使えない環境（プライベートウィンドウなど）では、key と辞書を保存できないことを画面に出し、その場限りで動かす

## 8. 画面

[mock/](mock/README.md) の 3 画面どおり。ルーティングはハッシュ（`#/`、`#/dict`、`#/setup`）で行う（GitHub Pages で 404 を出さないため）。

- `#/`：翻訳と読み上げ（Main）

## 9. 実装前に確かめること（未検証）

最初のマイルストーンで実測し、結果をこの節に追記する。

| # | 確かめること | 方法 | 駄目だった場合 |
|---|---|---|---|
| V1 | ブラウザから Groq を直接呼べるか（CORS） | 本番と同じオリジンから `fetch` する | Cloudflare Workers で、key を保存せず中継するだけの層を挟む |
| V2 | Edge で Natural の声（Nanami など）が `getVoices()` に出るか、`boundary` が来るか | Windows の Edge で声の一覧と発火するイベントを記録する | PC 内蔵の声（Haruka）を既定にし、ハイライトは文単位にする |
| V3 | 1 回あたりのトークン数と、1 日に使える量 | レスポンスの `usage`（または `x-groq` の usage）を記録する | 出力形式やプロンプトを削る |
| V4 | 「押してから声が出るまで」の時間 | `performance.now()` で計測。Windows の Edge で 10 回 | モデルの既定や段落の分け方を見直す |
| V5 | kuromoji の辞書の読み込み時間とサイズ | 初回と 2 回目（キャッシュあり）の時間を測る | 読み込みを後回しにし、届くまでは AI と辞書の読みだけで表示する |
| V6 | 2 つのモデルが Groq で使えるか | `GET /models` | 使えるモデルに差し替える |

## 10. テスト

Vitest で、画面に依存しないロジックをテストする。

- NDJSON の行分割とパース（行の途中で切れたチャンク、壊れた行）
- 読みの優先順位（§4.1）とトークン化（§4.2）
- 音声テキストの組み立てと位置の対応表（§5）
- 辞書の書き出し・読み込み（version 違い、同じ語の上書き）
